可靠性验证指标

以下指标是 ReliaScope 平台进行软件可靠性验证的核心依据，所有计算均基于 failures 表中的原始故障样本实时得出。每项指标均在「单目标验证」页逐条核对对应判据（criteria 表），全部满足方可通过验证。
失效率 λ MTBF 可靠度 R(t) 可用度 A 置信区间 致命故障数 数据质量 DQ 最低样本量 n G-O NHPP Weibull Duane / Crow-AMSAA

1失效率 λ（Failure Rate）

单位时间内发生失效的期望次数，是可靠性工程最基本的度量。ReliaScope 采用观测失效率（点估计），由全部有效故障样本直接计算。
λ̂ = n / T × 1000  （单位：/kh，即每千小时失效次数）
其中 n = 有效失效总数（counted ≠ false 的 failures 行数），T = 全部样本的 delta_t 之和（含剔除行）。
λ 越小表示软件越稳定。例如 Linux Kernel 的 λ = 0.01 /kh，意味着平均每 10 万小时才发生一次失效。

2MTBF（Mean Time Between Failures）

平均故障间隔时间，即两次连续失效之间的期望运行时间。MTBF 是失效率的倒数，直观反映系统的可靠性水平。
MTBF = T / n  （单位：小时 h）
判据阈值：≥ 500 h（可在「平台设置」页调整）。
例如 PostgreSQL 的 MTBF = 150,600 / 11 ≈ 13,691 h，意味着预期两次故障之间可连续运行约 19 个月。

3可靠度 R(t)（Reliability）

在规定时间 t 内、规定条件下，软件不发生失效的概率。ReliaScope 默认任务时间 t = 720 小时（30 天），假设失效服从指数分布。
R(t) = e−λ̂·t = e−(n/T)·720
判据阈值：≥ 0.9500。
指数假设意味着失效随机发生、失效率恒定（偶发失效期）。若 R(720h) = 0.9647，表示在未来 720 小时内不失效的概率为 96.47%。
该值受样本量 n 和总试验时间 T 共同影响：少量样本会导致估计方差大、置信区间宽。

4可用度 A（Availability）

稳态下系统处于可工作状态的时间比例，综合考虑故障和修复两个过程。
A = MTBF / (MTBF + MTTR)  （MTTR = 3.6 h，默认平均修复时间）
A 越接近 1 表示停机时间越少。例如 MTBF = 20,000 h 时，A = 20,000 / 20,003.6 ≈ 0.99982，年预期停机约 1.6 小时。
可用度不在判据表中，但作为参考指标在「分析计算过程」中展示。

5MTBF 置信区间（Confidence Interval）

点估计（单一数值）无法反映不确定性。ReliaScope 采用定时截尾试验模型，置信度 γ = 90%，给出 MTBF 的双侧区间估计。
θL = 2T / χ²(1+γ)/2, 2n+2
θU = 2T / χ²(1−γ)/2, 2n
χ² 分位数使用 Wilson-Hilferty 近似计算。R(720h) 的置信下限 = e−720/θU，在「验证结论卡」中展示。
判据：置信度 90%（双侧）。

6致命故障一票否决

统计有效样本中 severity = 致命 的故障数。任何致命故障的发生都是不可接受的——这是安全关键系统的强制性判据。
fatal = Σ [severity = 致命 ∧ counted = true]
判据：致命故障 = 0（强制项，不可停用）。
即使 R(720h) 和 MTBF 全部达标，只要有一个致命故障未整改，验证结论即为「不通过」。

7数据质量 DQ（Data Quality）

由 Agent T2 任务从六个维度对 failures 表做综合评分，评估故障数据的可信度。每个维度 0-100 分，按加权均值汇总。
DQ = w1·完整性 + w2·一致性 + w3·时效性
    + w4·准确性 + w5·唯一性 + w6·合规性
完整性：必填字段非空比例   一致性：seq 连续性 + 软件归属有效性
时效性：近 7 天有新样本的比例   准确性：delta_t 正值且离群值占比低
唯一性：重复行比例反向   合规性：severity / build 枚举合规比例
判据阈值：≥ 85 分。在「单目标验证」页目标 DQ = 88 + n/10。

8最低样本量 n

统计推断的基本前提：样本量过小会导致估计方差过大、结论不可靠。ReliaScope 要求有效失效样本数至少达到阈值。
n = Σ [counted = true]  （有效计入统计的 failures 行数）
判据阈值：n ≥ 8。
例如 Nginx 有 8 条有效样本，满足该判据；Linux Kernel 仅有 6 条，即使 R(720h) 高达 0.9857 仍被判定为「未通过」。

9G-O NHPP 增长模型

Goel-Okumoto 非齐次泊松过程模型，用于描述"随着测试推进，缺陷检出速率递减"的可靠性增长规律。Agent T1 任务负责对每个软件的累计失效序列做拟合。
m(t) = a · (1 − e−b·t)
a = 软件中预期的总缺陷数（模型估计）  b = 缺陷检出速率参数
拟合方法：对累计失效序列 (ti, i) 遍历 b 做网格搜索，每个 b 用最小二乘直接求解 a，以残差平方和最小为目标。
剩余缺陷 = a − n，用于「故障预测」页的前端实时估计。更精确的预测产物（p50_30d / p90_30d / rul_h）由 Agent 写入 predictions 表。

10Weibull 寿命分布

用于描述失效间隔时间的分布规律，通过形状参数 β 判断当前处于早期失效、偶发失效还是耗损失效阶段。
f(t) = (β/η) · (t/η)β−1 · e−(t/η)β
R(t) = e−(t/η)β
对失效间隔做中位秩回归：x = ln(t), y = ln(−ln(1−F))，其中 F = (i−0.3)/(n+0.4)。
斜率 = β（形状参数），η = e−截距/β（尺度参数）。
β < 1 → 早期失效期（磨合）  β ≈ 1 → 偶发失效期   β > 1 → 耗损失效期。

11Duane / Crow-AMSAA 增长模型

描述累计 MTBF 随测试时间呈幂律增长的趋势，广泛用于可靠性增长试验的跟踪与评估。
累计 MTBF(T) = a · Tα
对 (ln T, ln(T/n(T))) 做线性回归：斜率 = α（增长率），截距 = ln a。
α > 0.2 表示有明显增长趋势；α ≈ 0 表示 MTBF 不随测试时间增长。R² 衡量拟合优度。
