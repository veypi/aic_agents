需求验证指标

软件需求符合性验证的通用指标项、含义与计算方式

什么是需求符合性验证

需求符合性验证（Requirements Compliance Verification）回答一个朴素的问题：交付的软件，还是不是当初承诺要建的那个软件？ 它属于软件 V&V（Verification & Validation）体系中的「验证」一侧——以需求规格说明为基准，检查每一条需求是否被实现（追踪覆盖）、被正确实现（验证通过）、以及整体符合程度如何度量（指标聚合）。
没有度量就没有管理：指标体系把「差不多做完了」变成可计算、可比较、可追踪趋势的数字。一个健康的需求验证体系通常关注四类指标：
覆盖类

需求有没有被实现？覆盖了多少？——需求覆盖率、追踪完整率

验证类

实现得对不对？验得够不够？——验证覆盖率、通过率、用例密度

质量类

需求本身写得好不好？缺陷多不多？——可验证性、缺陷密度

过程类

需求稳不稳定？回归收不收敛？——变更率、重验收敛

01需求覆盖率Requirement Coverage Rate
需求被设计与代码实现覆盖的程度。一条需求只要存在至少一条有效追踪链接（完整实现 F 或部分实现 P），即视为「已覆盖」。
RCOV = Ncovered / Ntotal × 100%
口径要点：分母应排除已废弃条目；「部分实现」是否计入覆盖需在项目级约定。健康阈值：≥ 95%；安全关键领域（适航、军工）通常要求 100% 并逐条说明缺口。
02追踪完整率Traceability Completeness
追踪链路的闭环程度。前向追踪（需求→设计→代码→用例）回答「实现了没有」，后向追踪（代码→需求）回答「为什么存在」。双向均通才算闭环。
TCR = Nclosed / Ntotal × 100%
配套监控两个反向信号：孤立需求（无任何出链，可能漏实现）与孤儿构件（无法回溯到需求的代码，可能镀金或漏登记）。DO-178C 等标准将追踪完整性作为审定硬性前提。
03验证覆盖率Verification Coverage
拥有至少一种验证手段（测试 / 分析 / 评审 / 演示）的需求比例。实现覆盖看「做没做」，验证覆盖看「验没验」，两者必须分别统计。
VCOV = Nwith-case / Ntotal × 100%
经验法则：高优先级需求验证覆盖应达 100%；仅有实现没有验证手段的需求，在符合性判定中一律按「待验证」处理，不得视为符合。
04验证通过率Verification Pass Rate
已执行用例中通过的比例，是验证轮次最直观的结果指标。
VPR = Npass / Nexecuted × 100%（分母不含未执行）
必须配合阻塞率与失败率解读：通过率高但大量阻塞，说明验证环境或前置条件有问题而非质量好。回归基线通常要求通过率 ≥ 90% 且关键用例 100% 通过。
05用例密度Case Density per Requirement
每条需求平均拥有的验证用例数，衡量验证的深度而非广度。
CD = Ncases / Nreq（按优先级分层统计）
密度过低（<1）说明大量需求没有验证手段；密度分层要求常见为：高优先级 ≥ 2 条（正常 + 边界/异常各一），中低优先级 ≥ 1 条。密度异常偏高则提示用例冗余。
06缺陷密度Defect Density
单位规模内检出的缺陷数，用于在能力域、组件之间横向比较质量水平，识别问题高发区。
DD = Ndefects / Nreq　（或每 KLOC、每功能点 FP）
解读时区分检出密度（验证发现）与遗留密度（交付后发现）。某域密度显著高于均值，通常意味着需求澄清不足或实现复杂度高，应触发专项评审。
07需求变更率（稳定性）Requirement Volatility
统计窗口内基线需求被增、改、删的比例，反映需求集的稳定程度。
RV = (Nadd + Nmod + Ndel) / Nbaseline × 100%
变更本身不是坏事，但 每次变更都要级联重验：受影响的需求、追踪链接与用例需重新确认。变更率持续偏高（如单迭代 >10%）提示需求获取不充分或外部约束剧烈波动。
08需求可验证性Requirement Verifiability
需求本身的质量：是否含有可量化、可判定的验收准则。「系统应快速响应」无法验证，「响应时间 ≤ 200ms」可以。
VQ = Nverifiable / Ntotal × 100%　（弱词率反向监控）
常用检查手段：弱词扫描（「尽量」「适当」「灵活」「用户友好」）、原子性（一条只说一件事）、无歧义性与一致性评审。ISO/IEC/IEEE 29148 给出了良好需求语句的九特性。
09加权符合性总分Weighted Compliance Score
把多维指标聚合成一个可判定总分：各一级指标得分（0-100）按权重加权求和，与判定阈值比较得出「符合 / 偏离」结论。
S = Σ (wi × si)，其中 Σ wi = 1，判定线通常取 85
权重 wi 不能拍脑袋，工程上常用 AHP 层次分析法确定（见下节）。总分应随基线沉淀，形成跨版本趋势，而非一次性快照。
10重验收敛度Re-verification Convergence
变更触发级联重验后，重验工作清零的速度与彻底程度，衡量验证体系的回归能力。
RCV = Nreverified / Nneed-reverify × 100%　（辅以清零时长 Tclr）
待重验积压是隐性风险：它意味着当前「符合性」结论建立在过期证据上。发布前应要求 RCV = 100%，即不存在未重验的变更影响项。

指标聚合与赋权：AHP 层次分析法

多个指标如何合成一个总分？关键是权重从哪来。AHP（Analytic Hierarchy Process）把「哪个指标更重要」的主观判断结构化：两两比较构造判断矩阵，求特征向量得权重，并用一致性比率检验判断是否自洽。
① 两两比较按 1-9 标度对指标两两打分：1=同等重要，3=稍重要，5=明显重要，9=极端重要，倒数表反向。
② 构造判断矩阵n×n 正互反矩阵 A = (aij)，aij = 1/aji，对角线恒为 1。
③ 求权重计算最大特征值 λmax 及其特征向量，归一化后即为各指标权重 wi。
④ 一致性检验CI = (λmax − n)/(n − 1)，CR = CI/RI；CR < 0.1 判定通过，否则重新比较。
CR = CI / RI < 0.1　　CI = (λmax − n) / (n − 1)　　RI 查表：n=3 → 0.58，n=5 → 1.12，n=7 → 1.32
聚合前还需把口径各异的底层指标归一化到 0-100：正向指标常用 阈值法 s = min(100, x / 目标值 × 100)；负向指标（如缺陷密度）用反向映射 s = max(0, 100 × (1 − x / 容忍上限))。本平台当前判断矩阵 CR = 0.041，通过一致性检验。
